# Trading Strategy Improvement Plan v36
## Macro, Market Regime & Cross-Asset Intelligence
**Revision 3 — scope-controlled, pre-flight-ready master plan | Post-v35 | Paper only**

## 1. Objective and scope
Improve sustainable net profitability, execution quality, capital efficiency and risk-adjusted returns over the accepted v35 baseline. Shared market intelligence should condition existing strategies before new strategies are considered. Indicators are hypotheses, not instructions to buy or sell. Negative research findings are valid deliverables.

Do not divert v35 resources. Passive collection of otherwise irrecoverable evidence requires separate approval. Preserve v35 financial reconciliation, protective exits, profile ownership, execution targets, promotion gates and dashboard architecture. No live activation, database reset, paid subscription or trading-setting change without approval.

### Domain priorities
| Domain | Tier | Initial scope |
|---|---|---|
| Technical trends, momentum and volatility | Core | Existing data first |
| Crypto breadth and relative strength | Core | Eligible historical universe |
| Derivatives and positioning | Core | Existing funding, OI, liquidations where supported |
| Macroeconomic | Core | Calendar, release timing, surprises where available |
| Cross-asset | Core, conditional on feasibility | Minimal dollar, yields and equity proxies first |
| On-chain and cycle | Opportunistic/contextual | Low-cost, reliable slow context only |
| Capital flows and sentiment | Opportunistic/contextual | ETF, stablecoin and transparent sentiment context |

Core means prioritised research, not mandatory implementation of every indicator. Opportunistic domains cannot block core delivery. Options analytics are optional even within derivatives. No new provider integration without a documented research question, coverage, cost, licensing, expected incremental value and coordinator approval; paid sources require operator approval. No general headline, social media, LLM sentiment, geopolitical or institutional millisecond news trading in v36. Deferred carry/hedging stays deferred.

## 2. Architecture and ownership
Reuse FeedHandlers, Insights, Strategy, Scouts, Learning, AutoTrader, allocation, Position Management (PM), Paper Exchange (PEx), RSocket, historical replay, excursions, existing financial ledger, React dashboard and Grafana. No parallel execution, learning, ledger or allocation engine.

Feed ingestion owns source observations; a single logical point-in-time evidence contract owns immutable observation versions and availability semantics (reuse existing storage, not necessarily a new database). Insights owns canonical feature calculations, incremental warm-up, shared global and per-symbol caches, and regime snapshots. Strategy consumes immutable versioned snapshots; Scouts and Learning reuse the same feature definitions in replay. AutoTrader owns decisions/reservations, PM owns orders/positions and PEx execution evidence; financial reconciliation remains authoritative. UI models project source-backed state only.

Cache keys include feature/version, scope, venue, horizon, universe version and as-of observation identity. Calculate global features once; share candle histories and overlapping paths. Bounded caches, explicit invalidation on revisions, restart-safe warm-up, reference-counted subscriptions and cancellation. No widget or Scout recalculates canonical indicators independently. No synchronous external request on the execution hot path. Benchmark cache hit rate, duplicate computations, subscription counts, queue depth and latency before expanding domains.

Shared feature contract (domain-specific fields are optional typed extensions, not mandatory common fields): stable ID, category, value/units, scope, symbol/group, venue, horizon, observation time, first-observed time, availability time, source/version, calculation version, freshness, quality, confidence if supported, event/group ID, regime ID and universe version. Missing, stale, estimated, provisional and observed are distinct. Historical replay uses only information available at decision time.

### Shared cache and subscription contract
Before Wave 1 implementation, the coordinator approves one versioned snapshot/delta contract: canonical keys, owner, revision/generation, sequence, as-of time, freshness, quality, initial snapshot, reconnect/resync, gap handling, bounded retention and reference-counted acquire/release. Insights owns canonical calculation and invalidation; transport owns fan-out; UI Model.ts owns instance lifecycle and projection only. Revisions invalidate dependent current snapshots without rewriting historical as-of evidence. Consumers reject out-of-order generations and recover from gaps using a fresh snapshot. Separate replay namespaces from live state. Freeze interface fixtures before parallel UI/backend tasks; one named contract owner approves changes. Test multiple widget instances, reconnect, cancellation, revision, stale state and bounded fan-out before Wave 2/3 UI expansion.

#### WP12 deterministic episode registry
Before evaluating candidates, pre-register versioned episode definitions by domain, scope and horizon: causal start trigger, confirmation time, end/reset condition, hysteresis, cooldown, maximum observation window, overlap/merge rule, grouping key and missing-data policy. Freeze numeric thresholds from development data only; no holdout tuning. Examples: crossover starts at confirmed closed-bar crossing and ends at confirmed opposite crossing; repeated same-state bars are not new episodes. Persistent regimes start at confirmed transition and end at confirmed exit; volatility/breadth/funding/flow extremes use threshold entry and distinct reset thresholds; liquidation bursts merge within a predeclared quiet-period gap. Macro uses announcement groups and related phases. Cross-asset transitions respect sessions and stale gaps. A data gap cannot manufacture a new independent episode; mark censored/unknown boundaries.

Assign stable IDs from definition version, scope and causal start identity; preserve original episode identity across replay and restart. Merge overlapping/common-shock episodes for independence accounting using predeclared rules; keep raw event counts separate from clustered counts and effective N. An episode end known later may label research outcomes but must never leak into earlier decisions. Publish exact parameter values, fixtures and expected counts before each study; test persistent states, boundary ties, cooldown, gaps, simultaneous symbols, restart and replay equivalence. One canonical implementation serves Scouts, Learning and research UI; no specialist-local counting. If definitions change, version and recompute affected studies without mixing populations.

#### 17.8 Promotion and natural validation
Require chronological walk-forward, untouched holdout, positive incremental net expectancy after fees/spread/slippage/funding/impact as applicable, robust execution sensitivity, multiple-testing control, regime coverage and all v35 gates. #### 17.9 Sparse natural evidence and reporting

Material candidate changes require a new prospective validation cohort under existing gates. ## 4. Delivery sequence and gates
The WP0 pre-flight is mandatory before Wave 0. Only Waves 0 and 1 are authorised for detailed task breakdown after v35 acceptance. Later waves are provisional and refined using actual findings. Coordinator reviews scope at each exit; no speculative implementation tickets. Each gate requires named owner, evidence artifact, pass/fail/deferred decision and next action.

| Wave | Deliverables | Exit gate |
|---|---|---|

Seven stages including Wave 0, reduced from eight. Wave 4 can start as soon as an individual core finding passes research gates; it does not wait for every Wave 3 hypothesis. Optional domains and dedicated candidates are not on the critical path. Natural paper observation continues independently of engineering milestones. No requirement to wait for rare macro/cycle events to finish engineering.

## 6. Mandatory safeguards
No look-ahead, false independence, unrealistic execution, uncontrolled experiments or unsupported directional assumptions. Death/golden crosses, RSI extremes, funding, OI, liquidation, dominance, ETF/stablecoin/exchange flows, cycle signals, NFP/inflation and dollar moves are conditional hypotheses. No future data, revised-as-original values, touched-order fills, guaranteed stop prices, candle-path inference or fictional financial outcomes. No weakened protection or Learning gates. No automatic live activation. Preserve Paper operation and independent financial truth.

## 7. Progress and definition of success
Report per WP implementation, tests, deployment, runtime, coverage, empirical/paper evidence, performance, visual acceptance, blockers and next action. Separate engineering from market-dependent evidence. Report reused/new/redundant/rejected features, announcement groups, consensus/original coverage, technical/liquidation/regime episodes, cross-asset/optional source coverage, executable paths, accepted/effective evidence, candidate/validated/rejected/promoted profiles and conditioned strict eligibility. Do not inflate progress with correlated Scout counts. Deferred optional work is not an engineering failure.

Success means the system understands supported market conditions, detects meaningful transitions, learns which existing strategies benefit or should abstain, improves entry/exit/sizing/execution/allocation where justified, reconciles financial outcomes, monitors deterioration and rejects non-incremental features. The objective is profitable trading, not collecting every indicator.
